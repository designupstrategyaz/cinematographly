# scripts/ — the charter

Tools accumulate conventions or they accumulate chaos. These are the conventions; a new script that
doesn't follow them is a review comment waiting to happen.

**Looking for a tool?** `INDEX.md` in this folder lists every script, one row each, with its kind,
whether the runner runs its selftest, and the first line of its docstring. It is generated by
`gen_index.py`, so its counts are never written by hand. This file is the guide: the conventions,
and what the main tools are for.


> ⛔ **Every `python3 scripts/…` line in this skill assumes your shell is at the SKILL ROOT.**
> From anywhere else use the full path — `python3 <skill-root>/scripts/<tool>.py …`. The
> scripts resolve their *data* files relative to their own location, so they read the right
> `clients/` and `assets/` either way; it is only the command itself that needs the path.

## The rules

1. **Stdlib only, standalone.** No pip installs, no shared internal imports (the one exception:
   `script_score.py` imports the parser from `estimate_duration.py`, deliberately, so the two can
   never disagree about what a spoken line is). External binaries allowed: `ffmpeg`/`ffprobe` only,
   checked at runtime with a clear error. The one tool that needs more lives outside this folder on
   purpose: `assets/supers-gsap/` (Node, Playwright, GSAP) is an optional lane with its own tests, and
   nothing in `scripts/` depends on it.
2. **The docstring is the contract** — what it does, usage examples, exit codes, and **an honest
   "what it cannot do" section** where the tool's silence could be mistaken for approval
   (`script_score.py` and `slop_check.py` are the models).
3. **Exit codes:** `0` pass/done · `1` findings/refused · `2` usage/IO error. Gates return `1` so
   they can be chained in shell with `&&`.
4. **`--json` on anything whose output another tool might consume.**
5. **Single sources of truth are read, never restated:** costs from `clients/costs.<client>.json`,
   delivery specs from `assets/delivery-formats.json`, lineage from `SHOTS-<SLUG>.json`, measured script bands
   from `assets/script-bands.json`. A number
   hardcoded in a script is a bug with a delay on it.
6. **Refuse loudly, never guess silently.** Unknown preset → list the valid ones. Thin QA
   observation → refuse with the reason. Placeholder text still in a config → refuse to run
   (`render-mp4.py` does this for a reason that cost a real project a junk folder).
7. **Exactly two Resolve scripts, forever** (`render-mp4.py`, `resolve-production-console.py`), and
   each runs BOTH ways unchanged — sent through the Resolve MCP's `run_script` (no `os`, no `open`:
   hand data back in `result`) or pasted into the console. New Resolve capability is a CONFIG toggle
   inside the second, never a third file; `test_console_scripts.py` executes both, both ways.
8. **Every gate's output must be un-fakeable** — the skill-wide principle. A script that prints
   PASS without doing work teaches people to trust PASS; that is worse than no script.
9. **A new script ships with a smoke test** — either a `test_*.py`, or at minimum it must run
   clean under `run_tests.py` (compile + `--help` + its own self-check if it has one).

10. **A script that gates the PROSE follows the same rules as one that gates a file.**
    `skill_audit.py` is `run_tests.py`'s counterpart for `references/`: run it after adding or
    renaming a reference, and treat its exit 1 the same way.

## The gate — two scripts and a hook that the rest of the skill now depends on (2026-09-06)

- **`review_pack.py`** (3.1) — `make <job> <stage> --file …` writes `07-review/<stage>/<code>/index.html`, a static page
  for a client, with a 16-character code from the files' hashes. Once a stage has a pack, `gate.py approve` needs
  `--pack <code>`, the code in the Approver's words, the newest pack, and unchanged files.
- **`deliver.py`** (3.1) — after `export` is approved, one folder per platform in `10-export/DELIVERY/` (master copied,
  captions, cover frame, `delivery.json`). Posts nothing.
- **`gate.py`** — `open` validates `00-brief/CHECKPOINT.md` and the client profile §0 and
  registers the ACTIVE job; `approve` records a human's verbatim reply against a file and its hash;
  `preflight` prints the exact `generate_*` params for a linted prompt; `hook` is the PreToolUse
  entrypoint (`hooks/hooks.json` at the plugin root); `session` injects the job state at
  SessionStart; `reconcile` reports credits spent outside a linted prompt; `close`. Since
  2026-10-25 (from the direct-response trial):
  - `approve family:<FAMILY>` signs a family of inserts' start frames from one contact sheet, as
    one `frame:<SHOT>` row per member;
  - `log-external` records media made outside the gate (a website free generation, a recording, a
    derived file) with its hash, and `reconcile --files` lists every media file nothing accounts for;
  - `approve lock` and `approve export` are refused in an evaluation job;
  - `allow image|video --shots … --by … --quote …` records one approval for a batch of shots plus 2
    regens each (2026-10-26): covered calls are still linted, and go through without a prompt until a
    shot has used its generations.
  - Since 2026-10-28 (lessons from a supplement ad job): `allow resolve --scope edit,render --scripts N --hours H` covers a
    session's DaVinci Resolve scripts with one approval, the way `allow image|video` covers generations (starting a
    render, the AI Speech Generator and auto-captions stay denied; deletes, project switches and unreadable scripts
    still ask); `status` answers fast (prompts checked by hash, media hashes from a size/mtime cache in
    `.gate/hash-cache.json`) and `status --full` re-lints; `cast` is named for what it is — one cross-shot sign-off on
    top of the `character:<NAME>` approvals; `pre-lock --write` writes the cut, titles-off and picture-only renders as
    filled `render-mp4.py` copies in `07-edit/_queue/` and lists what `approve lock` still needs; `where` prints this
    install's folders; a CHECKPOINT `Client:` path from another machine is found by name in `CINE_CLIENTS` or a
    `_cine-clients/` folder above the job, and said so.
- **`client_files.py`** — where a client's file is on this machine (v2.53.0): the folder `CINE_CLIENTS` names, a
  `_cine-clients/` folder beside or above the job, the script or the working folder, then the plugin's own
  `clients/`. `batch_plan.py`, `beat_plan.py`, `estimate_duration.py` and `script_score.py` ask it for
  `costs.<client>.json` and `script.<client>.json`; until then they read the plugin's folder only. The order is
  `gate.py`'s, and the selftest checks the two agree. `client_files.py where costs.<client>.json` prints the file used.
- **`build_bundle.py`** — the installable bundle, built from an ALLOW-LIST (v2.58.0). Until then each release was zipped by
  hand, leaving out what someone remembered to leave out. Now nothing ships unless the list names it: the manifest, the hooks,
  the agents, the five top-level pages, `assets/`, `modes/`, `references/`, `scripts/`, and the templates of `clients/` and
  `memory/`. It refuses on a key-shaped token, on a manifest version the change list does not name, and, with `--names FILE`
  (a private list kept outside the plugin), on any listed name. `--list` prints what would ship. `--out` is required: it never
  writes to a default place.
- **`memory_home.py`** — where the studio's own history is (v2.54.0): the folder `CINE_MEMORY` names, or a
  `_cine-memory/` folder beside or above the job or the working folder. The plugin's own `memory/` holds templates
  only. `consolidate.py` and `evaluate_promotion.py` read and write there and refuse when there is none;
  `skill_audit.py` checks `memory/...` pointers against it, and counts them as unchecked when it finds none.
  `memory_home.py init` creates the folder; `where` prints it.
- **`job_tier.py`** — the one answer to "is this an evaluation?": `Tier: evaluation` in the checkpoint,
  an `_eval/` folder or an EVAL name. `gate.py`, `prompt_lint.py`, `pull_finals.py` and `export_qc.py`
  all ask it, so the ship refusal that makes the tier safe lives in one place.
- **`action_points.py`** — where to cut a generated action clip (2026-10-26): it measures the clip's
  motion and proposes the in point at the onset, the cut on the commit, the foley hit at the contact and
  the settle, plus a ramp for the burst only when the burst is slow, and writes them as Resolve timeline
  markers (EDL). The timing belongs to the edit because models ignore sub-second timing in a prompt
  (`references/editing-and-audio.md`, Action points). It proposes; the editor decides.
- **`motion_qa.py`** — the motion analysis picture lock refuses without (2026-10-26). `clip` measures a
  selected take's camera, framing (first, middle, last), the subject's direction as it enters and exits,
  its main action and the action points, and reports where they differ from the prompt's plan
  (`[CAMERA]`, `travel:`, `enter:`, `exit:`). `cut` measures every join of the cut and checks each
  planned hand-off (`join:`). `check` is what `gate.py approve lock` runs: a current report per shot in
  the cut, and a joins report on the newest cut (`references/shot-handoff.md` §4b). `--track
  name=x,y,w,h` (or `track:` in the clip prompt) follows a named object boxed on the first frame: its
  path, its direction, where it is at the cut and whether it leaves the frame, and the same object
  across a planned match in the cut. Since 2026-10-26 (the titles-and-motion
  review) `check` also holds the cut to its transition and ramp budgets, from `07-edit/timeline-dump.json`
  and the selected shots' `ramp:` and `join:`: at most 2 accent kinds (the title card's), a dip only at the
  end or a named act break, no transition on a dialogue clip, whips ≤ 2, one ramp per 20 s and 2 per video,
  and every slow-down cleared by `warp` — the frames of a ramp predicted from each other by dense flow,
  tears and frame-repeat stutter measured against the footage around it, on the cut as rendered. It notes,
  without refusing, a clip far slower than the other clips its model made (slow motion nobody asked for) and
  a clip whose frames repeat. `inventory` tags the templates `resolve-production-console.py`
  `INVENTORY_TEMPLATES` listed (family, use, stars kept across re-runs).
- **`aerial_qa.py`** — aerial, FPV, insect-scale and planet-scale shots (2026-10-26, lab-00016). `lint` is the `aerial:` declaration `prompt_lint.py` runs on every clip that carries one: a job
  (`function=`), a named subject, a last frame (`final=`), one move from `assets/aerial-moves.json` (an alias
  or a DJI preset works), no speed or miniature words, a reason for a nadir, real time at insect scale, no
  stars beside a lit Earth, simulated geography at planet scale, no Google Earth, and a real cleared photograph
  — or a declared `chain:` from one — under a real place. `chain-frame` pulls the next link's start frame from a
  measured, selected clip and records it (C1: three links at most). `scale`, `drift`, `seams` and `stars` measure
  the toy look, landmarks that re-form, hidden seams and stars, and only warn until real drone footage
  calibrates them. `check` is what `approve lock` runs: the rules refuse; the measures and the cut notes (an
  aerial under 3 s, a transition on one, drama's bookends, one stunt per film, the aerial share) warn.
- **`flyover.py`** — the golf and property flyover product (2026-10-26). `course init`
  writes the hole cards (`--preset old-course` carries only the checked facts), `course lint` refuses gaps and
  wrong sums, `hole prompt` drafts a declared clip on the hole's seed, `property init/lint` holds every room to
  its real photograph, `overlays` checks every hole card and room label against the cards, `rights` writes
  `09-qa/aerial/RIGHTS.md`, and `pilot` writes the pilot sheet for a real drone day: the DJI preset that flies
  each shot, what to set, the clearances from DJI's manuals, and a Waypoint table per hole. `check` runs at
  lock; a `private: true` card makes `gate.py` refuse to publish.
- **`title_card.py`** — the project's title card, the permission list for titles
  (2026-10-26). `propose` writes `00-brief/TITLE-CARD.json` from the lane's defaults
  (`assets/title-lanes.json`) and the brand's font files; `lint` reads those files with a stdlib OpenType
  parser and refuses faux styles, a redundant pair, no single scale, more than 5 durations or 3 curves,
  overshoot (C2), blur in ads, a long hero line, budgets over 2; `titles` holds every
  `07-edit/titles/<id>.title.json` to the card (kind, words, dwell by regime, its anchor after the 0.4 s
  settle — C1 — never across a transition or a ramp); `pick` takes the owner's choice among options;
  `check` is what `gate.py approve lock` (the card) and `approve titles` / `approve export` (every title
  measured and passing `title_qa.py`) run (`references/typography-and-captions.md` §6c). A spec's `engine` is
  `resolve` unless it says otherwise, and `hyperframes` or `gsap` needs an `engine_reason` (the native-elements rule).
- **`title_qa.py`** — the legibility gate for a title, on the composite over the cut (2026-10-26). `native` (2026-10-27,
  C7) measures a title made in Resolve on two of Resolve's renders of one timeline, the titles track on and off: the
  difference is the title, the off render the plate behind it → `<id>.native.qa.json`. `check` measures the safe box, the dwell from when the text is still, overshoot on the pixels, contrast
  against the worst frame behind the text, a 390 px phone proof (thinnest stroke, cap height), collisions
  with captions, faces and an `--avoid` box, and flashes; it writes `<id>.mov.qa.json` and a strip.
  `strip` sets a hero title's options side by side for the owner to pick from. Needs numpy (and OpenCV
  for faces); thresholds marked [assumed].
- **`mix_qa.py`** — the export audio gate (2026-10-26). `measure` reads the export, the dialogue stem and
  the bed (the mix with the dialogue muted and the ducking on), and checks that the stems are this mix,
  the VO over the bed while it speaks (full band and on a phone) against the floors, the short-term
  ceiling, the mono fold-down, room tone (silence, dropouts at cuts, the drama lane's ambience held
  across a scene), and that no non-dialogue take's own sound is in the mix unapproved. `manifest` and
  `licences` keep `09-qa/mix/AUDIO-MANIFEST.md`: every sound, its licence, and the known AI-audio blocks
  in `assets/ai-audio-licences.json`. `check` is what `gate.py approve export` runs
  (`references/editing-and-audio.md` §7b–§7e).
- **`sfx_conform.py`** — sound effects conformed to the shot (2026-10-26). `events` finds every visual
  event (each drop, step, tap) with the camera's motion and flicker removed; `read` puts their frames on
  one sheet with a closed-vocabulary form the agent fills by looking (material, surface, wet, size,
  force, seen or behind glass, the room, the distance, the true count); `index` lists every attack in a
  downloaded SFX file, or marks it a bed; `conform` cuts the file into its events, one per visual event,
  each 0 to +1 frame late, level, tone, room, pitch and (optionally) pan per event, and re-checks the
  render alone; `joins` plans the sound across each planned cut, with markers and an optional whoosh
  stem, and each planned ramp's mute window and cue (`references/editing-and-audio.md` §7f, § The ramp).
  `library build|search|pull|list` catalogues the machine's sound libraries; a build reads a vendor's UCS
  "Metadata Import" sheets (Ocular Sounds ships one per pack) for keywords, CatID, key and tempo, and
  `search --key C# / --bpm 120` filters on them (2026-10-27).
- **`music_fit.py`** — the music fitted to a motion-led cut (2026-10-26, lab-00017; music only, cut
  nudges suggested: the cut never moves by itself). `map` finds beats, downbeats, bars, phrases,
  sections, energy, the key and the ending (Beat This! when installed, then librosa, then numpy). `hits init`
  drafts `07-edit/music/HITS.json` from the timeline dump for the director to mark the 2–4 must-hits and
  declare the track. `fit` tries the library's cutdowns, then the in-point, whole-bar edits at phrase lines,
  one beat for a must-hit, and a pitch-kept stretch of at most ±2 %; it writes three plans with every hit's
  residual and the cut nudges (C1: 0 to +1 frame late, never early). `rebuild` (v2.50) writes the picked plan as
  the edit to rebuild IN RESOLVE from the original track — `07-edit/music/REBUILD.json` and `REBUILD.md` — and the
  console copy that places the original's segments on A5 with sparse markers and a marker per seam; crossfades and
  fades are done in Fairlight by computer control. `render` writes a 48 kHz **preview** to listen to, never imported
  into Resolve.
  `stems` and `arrange` mix the library's stems (Demucs on demand) to each section's energy, with one
  stop-down and the vocal muted under speech. `check` is what `gate.py approve export` runs: the rules
  refuse, the measures warn, read on the music stem exported from Resolve (`references/editing-and-audio.md`
  § Music to picture).
- **`script_score.py`** and **`beat_plan.py`** (v2.51) read `assets/script-bands.json`, the measured bands from
  the 2026-11-05 script corpus (`references/script-craft.md` §2d).
  - `script_score.py` prints the bands beside the script's own numbers: pace, word budget, CTA position,
    questions, contractions and, under `--ugc`, sentence length, fillers, connectives and the short-closer
    tell. They are advisory, never a FAIL. It warns only on a pace above p90, a CTA in the first 60 % of a
    short spot, or the short-closer pattern.
  - `--house` (with `--vo` for an ad's VO) is the explicit opt-in that takes `--max-words` from the band.
    Nothing becomes a silent default.
  - Contractions count with a straight or a curly apostrophe (SCR-01).
  - `beat_plan.py plan` prints where real spots put the CTA and how many words they speak in the runtime.
- **`fanout.py`** (v2.50) — the dispatcher's ledger for the plugin's parallel agents: `plan` (one output path per
  unit, `--writes` globs for writers, a snapshot of the job's text files), `record` (a read-only agent's report),
  `check` (silence is a FAIL; a typed header with an allowed verdict; nothing changed outside the brief) and
  `agents` (lints `agents/*.md`: minimal tools, read-only reviewers, one shell) — `references/parallel-agents.md`.
- **`region_repair.py`** (v2.49, v2.50) — one region of a good take repaired: `track` (box or SAM 2), `mask`,
  `fusion` (the matte grown and feathered, the track in Fusion coordinates and RECIPE.md for the comp built by
  computer control), `composite` (a `PREVIEW-` file only) and `qa` (`--render` on Resolve's render; drift reports,
  provisional).
- **`composer.py`** — the lead composer (2026-10-27, lab-00018: the skill drafts and a person edits
  the motif, the tiered window, consent first with a whitelist, AI vocals case by case, everything in
  Fairlight). `brief`/`spot`/`consent` the composer's paperwork; `motif draft`/`adopt` the client's motif, drafted
  by rules and edited by the owner (the diff kept, a melody check against the studio's kits and other clients); `key
  confirm`; `layer` impacts on the hard hits and the mnemonic as the button over the fitted bed; `family` the
  length family and the full alt mix; `solve`/`plan`/`realise`/`render` whole cues from a plan the agent writes,
  realised and validated by code (key, range, length, parallels, repeats), rendered by built-in synths,
  FluidSynth or sfizz; `gate-a` the outlier check against reference cues; `generated record`, `vocals record`
  and `bakeoff` the generated-bed trial; `elements` the element sheet; `console` the Fairlight copy of the
  console script; `check` what `approve export` runs (`references/editing-and-audio.md` § The lead composer).
- **`world.py`** — the world of an exterior, designed before the frames (2026-10-27, lab-00020; *"don't focus on the
  golf itself, but how the plugin approached the scenario"*). `init` the card (sun, Beaufort wind, WMO sky,
  visibility and depth layers, land, water, background life cast with numbers, the place's plausible life with
  sources); `check` its rules (what `approve world:<LOC>` runs); `cues` the prompt lines it implies; `accept` the ⚑
  warnings on a prompt before spend; `stop` / `close` a noticed problem; `override` a species off the list in the
  owner's words; `read` a returned clip against the card (what `approve clips` runs); `status`; `console` the
  world as Resolve markers. `prompt_lint.py` calls `lint_prompt()` on every frame and clip; `aerial_qa.py` adds
  the motion budget (`aerial: path_m=`). `references/world-design.md`.
- **`soundoff.py`** — the client's sound-off check (2026-10-27, lab-00019; *"does the video tell a story without
  sound and voiceover?"*). `proofs` silent copies of the captionless master or Resolve's picture-only render (T2)
  and of every delivery file (T1), each bound to its source's hash; `map init`/`set`/`waive`/`show` the story map,
  one row per beat of the approved script with its window on the cut (`--narrow` for a talking head: WHO, PRODUCT,
  PROOF, OFFER); `strip` one frame per beat, numbers only for the cold viewer; `placement` a sound-on-only plan in
  the owner's words (T1 advisory); `waive` a sound-led T2 or the cold viewer; `claims` the spoken numbers on
  screen; `console` the map as Resolve markers; `pack` the hand-over; `check` / `lock-check` what `approve
  export` and `approve lock` run. Verdicts are logged with `qa_log.py --gate soundoff` (a cold viewer's retell
  first, then at least three beats inside their windows and the offer). `references/sound-off-story.md`.
- **`srt_qa.py`** — the caption file measured (2026-10-27). FAIL: broken timing, overlaps, an empty cue, a pop
  chunk under 0.5 s. WARN [assumed for social]: over 20 cps, 2 lines, 42 characters a line, under 0.3 s a word —
  signed off with `accept`. `check-job` is what `soundoff.py check` reads.
- **`render-mp4.py PICTURE_ONLY`** (2026-10-27) — queues the T2 render from a duplicate of the timeline with the
  subtitle and caption tracks off and no audio; the editor's cut is never touched. **`TITLES_OFF`** — the same, with
  the title tracks off (the other half of `title_qa.py native`). **`BURN_SUBTITLES`** — Resolve burns the Subtitle
  track in (`ExportSubtitle` + `SubtitleFormat: BurnIn`); `srt_qa.py burned` then finds every cue in the pixels.
- **`native.py`** — on-screen text is made in Resolve (2026-10-27, the native-elements rule: Resolve's or
  Fusion's own elements by default, never made outside without a reason). `console <job> [--srt …]` writes the console copy
  with `PLACE_TITLES` (each resolve-engine title as the card's template on the `titles` track, its words set and read
  back) and `PLACE_SUBTITLES` (the `.srt` onto a Subtitle track, or as Text+ on `captions`); `reasons` lists the four
  an outside render may give (batch, derivative, remux, owner); `record` writes one; `check` is what `approve export`
  runs: a file ffmpeg made needs a record, a remux must be a stream copy, and Resolve's caption burn needs a
  `srt_qa.py burned` PASS on the file's bytes. Needs ffmpeg, and numpy for the pixel checks. Since 2026-10-28:
  `sync-specs <job> [--write]` rewrites each title spec's time, length and words from the timeline dump (the console's
  `DUMP_TIMELINE_JSON` now carries each title's words), and the console copy places titles the way Resolve 21.1.1
  was measured to need (every other track locked, the playhead and marks set, the words written inside
  `comp.Lock()`, a still exported per title, the track names, the timeline snapshot and its invariant).
- **Additions from a supplement ad job (2026-10-28)** — `sfx_conform.py levels` (each effect's gain from the voice's momentary
  loudness at that moment, by category, under a −6 dBFS ceiling, the in-point on the file's own transient);
  `music_fit.py bed` (the bed trimmed, seamed under speech, ended on the last frame, ridden, ducked and carved, at the

  photograph nobody looked at reaches a delivered frame. `adopt` records the human's pick, moves it

  and one still `NOT CLEARED` that is not explicitly `--use reference-only`. A `what: voice` slot is

- **`prompt_lint.py`** — a prompt is a file with a shape (`--template clip|frame`), and the lint

- **`test_gate.py`** — the suite: from an empty folder through development, the frame gate, an allowed clip call, picture lock and export. It is also

1. **`gate.py hook` fails CLOSED.** The usual hook convention says a hook must never block on its own error. A spend gate that fails open

2. **`prompt_lint.py` and `gate.py` share `normalize_prompt()` by copy, not import** — rule 1 says
   standalone; the two copies are asserted identical by `test_gate.py` (a hash mismatch between

## The production ledger (2026-09-08) — `ledger.py`

The gate is a **quality gate for one video at a time**, and it was never built to be a production
tracker for a month of them. `active-job` holds exactly one job per `CINE_HOME` and expires in 24 h;
nothing enumerates job folders; nothing sums anything across videos. Fine at 2–3/month, and the
binding problem at 30–50.

`ledger.py` adds the missing layer. `00-brief/RECORD.json`, one per video, **derived** from the
artifacts the gate already forces to exist and written by `gate.py` on `open`, every `approve` and
`close` — because in this codebase, every piece of state that needs a second command has gone quiet
under load (`shot_manifest.py add`, `qa_log.py`, `EPISODES.md`, `COSTS-*.md` are all manual and all
degrade). Only identity (`ad_name`, persona, …) and the terminal facts (`kill`, `deliver`,
`signoff`, `note --blocked`) are authored, because nothing on disk implies them.

Three things it fixed that were defects rather than gaps:

1. ⛔ **`--allow` did not exist.** `gate.py approve script`'s own refusal text said to re-run with
   `--allow "<phrase>"`, and there was no such flag — so a phrase the client had approved in writing
   could never pass. An instruction that cannot be followed teaches people to reach for
   `CINE_GATE=off`. It exists now, and the phrase and its approver land on the record.
2. ⛔ **The claims check was not persisted.** It ran, printed, and was forgotten, so *"which shipped
   videos contain this claim"* had no mechanism. Findings, allowed phrases and the disclosure state
   are now on the record, and the approved script copies itself into `script-archive/` — the corpus
   `ledger.py find --claim` searches, which was empty because populating it was a convention with no
   tool.
3. ⛔ **A killed script left no trace.** The approvals ledger is append-only positives; the archive
   takes finals only. `ledger.py kill --why` is the missing state, and it refuses without a reason.

`ledger.py find` reports **how many records and how many archived scripts it searched**, and returns
**INCONCLUSIVE rather than clean** over an empty corpus — the SILENT PASS rule, which is exactly the
shape a recall query would otherwise fail in. `ledger.py index` prints its own holes (no manifest, no
join key, no claims record) rather than a clean-looking table.

⚠ It searches *approved scripts*. A claim added in the edit, improvised in a VO, or burned into an
overlay is outside the corpus — the audio-text lock is what makes the script a truthful proxy. An
adversarial read the same day found four more false negatives, all now fixed and pinned: a claim
wrapped across a line break, a job under a `_`-prefixed directory (`_series/` — this skill's own
convention), a non-UTF-8 file crashing the query into a "no match" exit code, and a record whose
archived script has moved. And two defects in the gate that made the whole feature theatre: the
client's `Claims-category` **never reached the lint** (`cmd_approve` never called `validate()`, and
the regex did not match the profile's real markdown), so only the universal rules ever fired.

Also landed: `batch_plan.py --out` writes the matrix as JSON. It used to print the month's entire
design — every ad-name join key — to stdout and instruct a human to paste it into a markdown file,
so every downstream join depended on a manual transcription.

**Landed 2026-09-08, closing three of those:** `ledger.py month` is the monthly rollup — and it
reports a **denominator on every figure**, because a credits total built from three videos that
recorded them and thirty that did not is a floor, not a total, and it says so. `pull_metrics.py` is
the metrics writeback (below). `pull_metrics.py hooks --write` generates `HOOKS-USED.md` from
ingested data, so the hook register stops being a file the docs assume somebody maintains by hand.

**Still no writer:** `EPISODES.md` and `COSTS-<SLUG>.md`.

## The metrics writeback (2026-09-08) — `pull_metrics.py`

`performance-metrics.md` designed this in August and named the tool; the tool did not exist, so **no
performance data had ever entered the skill from any platform.** "Which hooks have we used and how
did each do" was unanswerable, which makes the hook bank a list of guesses and the promotion floors
decorative.

⛔ **The research finding that shaped the whole file: none of the four platforms has a fixed export
schema.** The header row is whatever columns the user ticked in the UI; no platform publishes a
default set or a header list; and the headers *are* the UI display strings, so they change with the
account's language. A positional parser is guaranteed to be wrong eventually and **silently**. So:
column-name driven, every unrecognised header **quarantined and named**, `--map "Header=field"` to
close one without a code change, Meta's summary/totals row dropped (it carries no ad name and would
add a phantom video holding the month's whole spend), and locale-safe number parsing because Google
Ads documents both `2,000.50` and `2.000,50` and nobody documents an export-locale override.

⛔ **"Views" is not one quantity.** TikTok counts a view when playback *starts*; Instagram counts
replays; Meta's paid ladder has no "views" column at all; YouTube redefined the word twice in
eighteen months. So `report` groups by platform and **refuses to total across them**, and only Meta
rows are scored against the weak/strong bands in `performance-metrics.md` §1 — those bands were
derived on Meta's 3-second metric, and TikTok's nearest equivalent is a *2-second* one. Everything
else is marked **UNBENCHMARKED** rather than graded against a band it was not built from.

⛔ **The organic join is ours to make.** No platform guarantees a field we control in its export, so
`ledger.py publish --post-id/--url` records it at upload time. A row that matches nothing is
reported **UNATTRIBUTED**, never dropped, and an ingest that joins nothing **exits non-zero** — that
is an identity-layer failure, not evidence the videos underperformed.

**An adversarial read the same day found eleven defects, most of them silently wrong numbers.** All
fixed and pinned; the ones worth knowing about because they show the shape of the risk:

- **N rows per ad were overwritten, not summed.** Any export with a breakdown (Day, Placement, Age)
  has one row per ad per breakdown — and the alias table maps `Day`. A routine 3-day Meta export of
  one ad recorded **204.44 of 612.44** spend and printed *"joined 3 of 3"*. Now grouped and summed,
  with non-additive fields (reach, frequency, any rate) **dropped with a note** rather than summed
  or silently averaged.
- **Bare-dot thousands.** The ambiguity heuristic existed only on the comma branch, so `1,234` read
  as 1234 and `1.234` read as **1.234**. A German export's 12.480 impressions became 12.48, and the
  CTR computed from them read **769%, graded "strong"**, with no warning.
- **A keyless row was counted as a totals row and discarded.** A Meta file with boosted posts threw
  away real rows carrying real spend and printed *"joined 2 of 2 · exit 0"*. A row is now only a
  totals row if it is last **and** its numbers equal the column sums.
- ⛔ **The promotion gate was structurally broken.** The bank average included the hook's own reads,
  so a hook scoring 42% on two videos — *strong* by the file's own band — became its own average,
  lost twice, and was written into `HOOKS-USED.md` as **RETIRE**. PROMOTE was mathematically
  unreachable for a hook alone in the bank, which is exactly the state of an 8-video trial. Now
  leave-one-out, with a strict `<` for a loss and **"IN TEST — no comparison set"** when there is
  nothing to compare against.
- **Near misses joined the wrong record.** `RT ACME-B1-H05-P1-a` and `ACME-B1-H05-P1-a` are
  different ads; the key embedded in a longer name is now a *candidate*, reported, and accepted only
  with `--fuzzy`. Two videos sharing a join key are **refused**, not resolved by sort order.
- Accounting negatives lost their sign (`(1,234)` → +1234, a refund becoming spend); `<0.01` became
  an exact 0.01; a missing impressions value printed as a measured `0`; and TikTok's `video_views`
  was stored as a string because the field was missing from the numeric set.

**Still not built, and named:** no API leg; XLSX refused rather than parsed; no golden fixtures
(nobody publishes a header row, so the alias table is what we have verified, never a schema); no
quartile-cliff or CVR stage — `p25`–`p100` and `conversions` are parsed and stored but not yet
analysed, so `change_next` covers three of the waterfall's five stages; `report --month` filters on
the job's **open date**, not the metrics period, because an export's date range is not yet recorded;
and `ledger.py month` does not check currencies **within** one platform.

`hooks` applies the two-witness bar honestly: a hook must beat the bank average on **two separate
videos**, each above the impression floor. Two platforms on one video is one witness — it is one
video's luck measured twice. The floor itself is a practitioner range `[SECONDARY]`, not a platform
rule, and the tool says so every time it prints it.

## Roadmap (named, honest, not built)

- `claims_lint.py --lang ro` — the Romanian claims table (a Romanian voice scanner is outside this plugin; the
  *claims* lint does not exist yet).
- Word-level SRT from TTS timestamps (`build_srt.py` upgrade — documented in `editing-and-audio.md`).
- `build_srt.py --conform timeline-dump.json` — retime cues to a human-edited cut using the
  `DUMP_TIMELINE_JSON` output from the console script (the conform bridge; designed, not built).
- Live-Resolve verification of the `DUMP_TIMELINE_JSON` toggle, `PLACE_TITLES`, `PLACE_SUBTITLES` (the `.srt`
  import is a probe) and `BURN_SUBTITLES` (all written against the documented API and tested on the fake; none yet
  exercised on a running Resolve from a session).
- a frame-QA prescreen — **partly built**: `clip_qa.py` now measures the *temporal* defects
  (dead zones, focus decay, whether the clip eases out, and how much motion runs past the spoken
  line) with ffmpeg alone. Still unbuilt:
  automated blink counting, identity drift by face-embedding distance, and flicker
  (`realism-qa.md` §7 roadmap). ⛔ `clip_qa.py` finds three mechanical defects; it cannot say a clip
  is good, and its focus metric is conservative by a wide margin (see its docstring).
- `frameio_comments_to_edl.py`: the EDL dialect is **unverified against a live Resolve import** —
  it emits the documented CMX3600 marker convention and its selftest proves the parser, not the
  import. Verify once on a real timeline, then delete this line.
- A review-platform API helper (share creation, ingest, comment pull, approval-status writeback):
  ⛔ **the blocker is gone.** It was blocked on whether a self-serve Frame.io account can use the API
  at all; the account now runs a **self-hosted** instance, where the answer is yes by construction
  (`review-and-approval.md` §9). What it needs first is the instance's own capability check — does it
  expose an API, and do comments export in a Frame.io-shaped CSV? If they do,
  `frameio_comments_to_edl.py` already works against it.
- `pixabay_search.py --type audio` — **not built, and not buildable today**: there is no documented
  Pixabay audio endpoint. The undocumented `/api/audio/` path resolves at the router but is
  [UNVERIFIED] and unsupported; music stays a manual website pull into `06-music/` with a
  hand-written provenance sidecar (`references/stock-sourcing.md` §8).
- No Pexels / Unsplash / Openverse adapters, deliberately: **Pixabay forbids hotlinking and Unsplash
  requires it**, so one fetcher across two libraries breaks one library's terms silently. One
  library per pipeline. Also unexercised in `pixabay_search.py`: the **full-API-access** image
  branch (`fullHDURL`) — coded from the docs, never run against an approved key.
- An eval runner: `claude -p` headless per eval case in Claude Code, judged against
  `expected_output` by a cheap model via a model router. Until it exists, the
  promotion gate's "eval non-regression" is a manual read.

## Measuring the time (2026-08-29)

`stage_timer.py start <stage>` / `stop` / `report` writes an append-only log to
`99-costs/stage-time.jsonl` and reports actuals against the runbook's budget. It exists because
**6.5 h per video is measured in aggregate and completely unallocated** — no one knows which stage
eats it, so every optimisation is a guess until a few videos are logged. ⛔ It measures *declared
wall-clock*, not work: leave the desk without `stop` and it charges you for the walk.

## The series layer (2026-08-29)

`series_registry.py` is the only script that operates *above* a project. `init` scaffolds
`_series/<BRAND>/`; `check` validates it. The column that earns its keep is **invariants version** —
without it, editing the bible silently reclassifies every past episode as non-compliant, and with it
a bible change produces a list of exactly which episodes a retroactive rule would touch.
⛔ Structure only: it cannot tell you an episode is on-model. See `references/series-continuity.md`.

## The speaking-clip gate, in two halves (2026-08-28)

`lipsync_check.py` transcribes a clip's own audio and scores it against the scripted line;
`qa_log.py` requires a **quoted word you heard** for a PASS on a speaking shot, checked against that
line when you pass `--line`, with the shot's kind read from the manifest so the gate cannot be
dodged by omitting a flag. Neither half is sufficient: the script verifies **content**, the human
verifies **articulation**. A PASS from only one of them is the 2026-08-18 mistake with better
tooling.
